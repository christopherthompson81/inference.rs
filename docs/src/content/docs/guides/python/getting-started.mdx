The Python SDK loads the model in-process. It is a pure-Python package over `libinference_ffi`, the C ABI of the same Rust engine that backs the `inference` binary.

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedPlain(model_id="Qwen/Qwen3-4B"),
    runtime=t.RuntimeSpec(isq="4"),
)

with ir.Engine(spec) as engine:
    response = engine.chat(
        t.ChatCompletionRequest(
            model="default",
            messages=[
                t.Message(role="user", content="In one sentence, what is Rust known for?")
            ],
            max_tokens=256,
        )
    )
    print(response.choices[0].message.content)
```

The first run downloads the weights into the Hugging Face cache.

## Installing

inference.rs does not publish wheels yet. Build the library from a checkout, then install the package. Python 3.10 or newer.

```bash
cargo build --release -p inference-ffi
pip install -e bindings/python
```

Add `--features cuda` (NVIDIA) or `--features metal` (macOS) to the `cargo build` for GPU support; see [cargo features](/reference/cargo-features/) for the feature flags and [hardware support](/reference/hardware-support/) for what each backend covers.

The package needs no compiled extension; `ctypes` loads the library on first use. It looks in `INFERENCE_NATIVE_DIR` first, then in `target/release` and `target/debug` of the checkout the package sits in, then in the platform's own library search path. To use a library built elsewhere, point the variable at its directory:

```bash
export INFERENCE_NATIVE_DIR=/path/to/dir/with/libinference_ffi
```

The package checks the library's ABI version when it loads it and refuses a mismatch, so rebuild the library after updating the checkout.

## The pieces

[`Engine`](/reference/python/engine/) owns the loaded model. Construction loads the weights; reuse one engine for the lifetime of the process to avoid reloading. Close it, or use `with`, to release it.

[`EngineSpec`](/reference/python/spec/) says what to load and how to run it; it is the JSON form of the options `inference serve` takes. Its `model` is a `ModelSelected` variant. `t.ModelSelectedPlain(model_id="...")` is correct for standard text models. Other variants cover multimodal models (`t.ModelSelectedMultimodalPlain`), GGUF checkpoints (`t.ModelSelectedGGUF`), embeddings (`t.ModelSelectedEmbedding`), and LoRA adapters (`t.ModelSelectedLora`).

`runtime=t.RuntimeSpec(isq="4")` is the equivalent of the CLI's `--isq 4`: it applies [ISQ (in-situ quantization)](/reference/quantization-types/), quantizing the weights to 4 bits at load time. Omit it for full precision. `RuntimeSpec` also takes the device (`device="cuda:0"`), seed, chat template, and paged attention settings.

Requests and responses are dataclasses from `inference_rs.types`, generated from the server's OpenAPI document, so they carry the OpenAI field names. Failures raise `ir.InferenceError`, whose `code` is the protocol's error code.

Full example: [plain](/examples/python/plain/).

## Streaming tokens

Set `stream=True` and call `chat_stream` to receive events as they are generated:

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedPlain(model_id="Qwen/Qwen3-4B"),
    runtime=t.RuntimeSpec(isq="4"),
)

with ir.Engine(spec) as engine:
    request = t.ChatCompletionRequest(
        model="default",
        messages=[t.Message(role="user", content="Write me a haiku about ownership.")],
        max_tokens=128,
        stream=True,
    )
    with engine.chat_stream(request) as stream:
        for event in stream:
            if event.name == "chunk":
                print(event.data.choices[0].delta.content or "", end="", flush=True)
    print()
```

Each event has a `name` and `data`. A `chunk` event's data is a `ChatCompletionChunkResponse` with the OpenAI streaming shape. `choices[0].delta.content` carries one incremental piece of the reply; it can be `None` (for example on the final chunk, which carries `finish_reason`), which is why the example falls back to `""`.

Full example: [streaming](/examples/python/streaming/). For async iteration, FastAPI integration, and mid-stream error handling, see [streaming from Python](/guides/python/streaming/).

## Notes

The engine keeps the model in memory until it is closed. Requests can be sent sequentially or from multiple threads; engine calls release the GIL, and all of them reuse the loaded weights. To swap models, close the engine and construct a new one.

Chat history is not tracked. Each call to `chat` is independent; multi-turn conversation means assembling the `messages` list yourself, appending each new user question and prior assistant reply.

The full Python surface (embeddings, speech, image generation, multimodal requests) is documented in the [Python reference](/reference/python/).
