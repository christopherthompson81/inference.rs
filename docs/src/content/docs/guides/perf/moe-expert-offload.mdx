---
title: MoE expert offload
description: Keep a mixture-of-experts model's experts in host memory with a hot cache on the GPU.
---

A mixture-of-experts model reads only a few of its experts per token, but the experts are most of its weights. With `--moe-expert-cache N` the experts stay in host memory, each MoE layer keeps the `N` experts it routed to most recently on the GPU, and the CPU runs the rest while the GPU runs the cached ones. Everything else (attention, recurrent layers, shared experts, the head) stays on the GPU.

```bash
inference serve --format gguf -f Qwen3.6-35B-A3B-UD-IQ4_XS.gguf --moe-expert-cache 64
```

It applies to GGUF experts on a CUDA device; other weights and backends load as before.

## What it costs and frees

Routing reuses recent experts heavily, so a modest cache serves most picks: on a 256-expert, 8-per-token model, 64 cached experts per layer served about 77% of decode picks in an agent session and 128 about 92%. A miss is computed on the CPU from host memory, and copied into the cache in the background so the next use of that expert is a hit.

The freed VRAM goes to the KV cache: the planner leaves the offloaded experts out of the device budget (keeping the cache slots and one layer's staging buffer), so the same GPU holds a much longer context.

| 35B-A3B (IQ4_XS), RTX 3090 | experts in VRAM | decode tok/s | available context |
|---|---|---|---|
| resident | 14.4 GiB | 180 | 100K tokens |
| `--moe-expert-cache 128` | 7.2 GiB | 98 | 467K tokens |
| `--moe-expert-cache 64` | 3.6 GiB | 52-63 | 652K tokens |

Decode speed depends on how fast the CPU reads memory (misses) and on the cache's hit rate; prompts copy each layer's experts to the GPU in turn, so their speed is bounded by the PCIe link (about 400 tokens a second on PCIe gen3 x16 for this model).

## Notes

- Decode steps stay inside CUDA graphs: the GPU finds each expert's slot in a table in pinned host memory and runs the cached experts while a host function on a side stream runs the misses.
- Output can differ between runs at the same seed: whether a pick is served from the cache or by the CPU depends on when its background copy lands, and the two round activations differently.
- Perplexity moves by a fraction of a percent: the CPU quantizes its activations per 256 values, the GPU kernels per 32.
- LoRA adapters on the experts and tensor parallelism are not supported with offloaded experts.
