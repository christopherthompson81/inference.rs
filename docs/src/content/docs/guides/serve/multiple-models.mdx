title: Serve multiple models from one process
description: Load several models into one inference server. Route requests by the model field, unload models to free memory, reload them on demand.

import { Tabs, TabItem } from '@astrojs/starlight/components';

`inference serve -m <model>` loads exactly one model. To host multiple models in one server, use a TOML config and `inference from-config`.

## Starting a multi-model server

Create `models.toml`:

```toml
command = "serve"
default_model_id = "Qwen/Qwen3-4B"

[server]
host = "0.0.0.0"
port = 1234

[[models]]
model_id = "Qwen/Qwen3-4B"

[models.quantization]
quant = "4"

[[models]]
model_id = "google/gemma-4-E4B-it"

[models.quantization]
quant = "4"
```

`quant = "4"` has the same behavior as `--quant 4`: it selects a matching artifact for a GGUF
repository. For other repositories, it prefers a prebuilt UQFF and falls back to 4-bit
[ISQ (in-situ quantization)](/reference/quantization-types/) during loading. Use
`isq = "4"` to force ISQ, or omit both settings to load at the source precision.

Start with `from-config`:

```bash
inference from-config -f models.toml
```

Routing rules:

- Each `[[models]]` entry is one loaded model, running on its own engine.
- A request targets a model by its `model_id`.
- `default_model_id` (if set) must match one of the `model_id`s.
- It is used when a request omits `model` or sends `"default"`.

`kind` is optional and defaults to `auto`; set it only when you need to force a loader.

## Routing a request to a specific model

Target a model by id. Omitting it (or passing `"default"`) selects the `default_model_id`, or the first model when none is set.

<Tabs>
<TabItem label="HTTP">

The `model` field selects the target:

```bash
curl http://localhost:1234/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "google/gemma-4-E4B-it",
    "messages": [{"role": "user", "content": "Hello!"}]
  }'
```

</TabItem>
<TabItem label="Python">

Against a running multi-model server, an OpenAI client sets `model` to the target id:

```python
from openai import OpenAI

client = OpenAI(base_url="http://localhost:1234/v1", api_key="not-used")

response = client.chat.completions.create(
    model="google/gemma-4-E4B-it",
    messages=[{"role": "user", "content": "Hello!"}],
)
print(response.choices[0].message.content)
```

In process, the Python bindings serve several models from an engine spec's `models`, and add or remove them at runtime (`add_model`, `remove_model`).

</TabItem>
<TabItem label="Rust">

Every request method on `Model` has a `_with_model` variant taking an optional id; `None` selects the default:

```rust
let response = model
    .send_chat_request_with_model(messages, Some("gemma-vision"))
    .await?;
```

The id is the model's `model_id`, or its alias when added with `add_model_with_alias`. See the `MultiModelBuilder` below for loading the models.

</TabItem>
</Tabs>

## Listing loaded models

```bash
curl http://localhost:1234/v1/models
```

Each entry includes `id`, `object`, `created`, `owned_by`, plus optional `status` (`loaded`/`unloaded`/`reloading`), `tools_available`, `mcp_tools_count`/`mcp_servers_connected` for [MCP (Model Context Protocol)](/guides/agents/connect-mcp-server/) servers, `max_model_len`, the longest sequence a loaded model accepts, and `default: true` on the model a request without `model` goes to.

## Unloading and reloading on demand

`POST /v1/models/unload` frees a model's memory, `POST /v1/models/reload` brings it back, and `POST /v1/models/status` queries its state; each takes `{"model_id": "..."}`. `GET /v1/models/cache_stats` reports each loaded model's cumulative prefix- and encoder-cache counters. Request and response schemas are in the [generated HTTP API reference](/reference/http-api-generated/).

## Adding and removing models at runtime

On a server started with `--allow-model-management`, `POST /v1/models/add` loads another model beside the served ones; its body is one entry of the spec's `models` (`{"model": {...}, "model_id": "..."}`, with the same per-model overrides), and it loads with the server's runtime settings. `POST /v1/models/remove` stops serving a model and frees it, `POST /v1/models/default` changes the model a request without `model` goes to, and `POST /v1/models/alias` (`{"alias", "model_id"}`) lets requests name a model by another id. The routes are off by default because adding a model reads any local path or hub repo the server can reach. The same operations are in the C ABI (`inference_model_add`, `inference_model_remove`, `inference_model_set_default`, `inference_model_alias`) and the C# and Python bindings.

## Multi-model from code (Rust)

In process, the Rust SDK loads several models with `MultiModelBuilder`; the bindings do it with the engine spec's `models` and the model management calls above. Route per request with the `_with_model` methods shown above.

```rust
use inference::{IsqType, MultiModelBuilder, TextModelBuilder, MultimodalModelBuilder};

let model = MultiModelBuilder::new()
    .add_model(TextModelBuilder::new("Qwen/Qwen3-4B").with_isq(IsqType::Q4K))
    .add_model_with_alias(
        "gemma-vision",
        MultimodalModelBuilder::new("google/gemma-4-E4B-it").with_isq(IsqType::Q4K),
    )
    .with_default_model("Qwen/Qwen3-4B")
    .build()
    .await?;
```

When setting `[models.device]` in TOML, `cpu` must be consistent across every model entry.
