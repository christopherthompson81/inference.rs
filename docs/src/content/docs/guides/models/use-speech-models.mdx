import { Tabs, TabItem } from '@astrojs/starlight/components';

inference.rs supports seven speech-related model families:

- **Parakeet**: NVIDIA's FastConformer speech recognisers (CTC, RNN-T and TDT heads), and the cache-aware
  Nemotron streaming ASR, served via `/v1/audio/transcriptions` with word and segment timestamps.
- **Nemotron-3 Diarization**: who speaks when (up to 8 speakers), served via `/v1/audio/diarization`.
- **Streaming Sortformer v2**: who speaks when (up to 4 speakers), from its `.nemo`, also via `/v1/audio/diarization`.
- **Silero VAD**: voice activity detection, served via `/v1/audio/vad`; it also cuts long recordings for Parakeet.
- **Voxtral Realtime**: multimodal model accepting audio input for speech transcription through
  `/v1/chat/completions`.
- **Dia**: dedicated text-to-speech model served via `/v1/audio/speech`.
- **Kokoro**: an 82M-parameter text-to-speech model with preset voices, also served via `/v1/audio/speech`.

Voxtral Realtime is classified as a multimodal model because audio is an input modality. Parakeet is a
dedicated transcription model, and Dia and Kokoro are dedicated speech models.

## Parakeet: speech recognition

```bash
inference serve -m nvidia/parakeet-tdt-0.6b-v3
```

The auto-loader recognizes Parakeet from the transformers layout (`config.json` with `model_type`
`parakeet_tdt`, `parakeet_rnnt` or `parakeet_ctc`, `processor_config.json`, `tokenizer.json`,
`model.safetensors`), or from NVIDIA's `.nemo` (the file, a directory holding one, or a Hugging Face repo whose
only checkpoint it is). A `.nemo` also loads the models with no transformers port, such as the hybrid RNN-T/CTC
FastConformers (`nvidia/stt_en_fastconformer_hybrid_large_pc`, decoded with its RNN-T head), and the
English streaming model; Nemotron-3.5 loads from its transformers files. NVIDIA's own `q8_0.gguf` of
these models (`general.architecture = asr`) loads too, its 8-bit weights dequantized at load: transcripts track
the full-precision model's to within a few words on hard audio, where the `.nemo` matches it exactly. A repo's
transformers files win over the GGUF beside them, so pass the downloaded `.gguf` path to load it.

A finer GGUF can be written from a `.nemo` with `inference quantize asr -m <.nemo, directory or repo> -o <file>
--policy <name>`. `--policy` takes a preset or the type every matrix takes; `q8_0`, the default, reproduces
NVIDIA's file byte for byte. `q8_0-decoder` keeps
the decoder and joint at F16, about 2% larger, which removed a third to two thirds of the 8-bit word errors in
our measurements. `q6_k-mix` (Q6_K, the feed-forward at Q8_0, the decoder at F16) is about 6% smaller than
NVIDIA's file and still more accurate. `--keep <name fragment>=<type>` sets the type of any other matrices. `parakeet-tdt-0.6b-v3` transcribes 25 European languages and identifies the language
itself. Audio in any format the decoder reads (WAV, MP3, FLAC, OGG, ...) at any sample rate is resampled to
16 kHz; recordings up to 24 minutes are transcribed in one pass, the bound NeMo gives for these models' full
attention.

`/v1/audio/transcriptions` takes OpenAI's multipart form. `response_format` is `json` (the default),
`text`, `srt`, `vtt` or `verbose_json`; `verbose_json` carries the duration and segments, and words too
when `timestamp_granularities[]` includes `word`. Timestamps are on the encoder's 80 ms grid. Parakeet
accepts and ignores `language`, `prompt` and `temperature`: it identifies the language itself.

Decoding is greedy unless `beam_size` (1 to 16, an inference.rs field) asks for a beam: NeMo's batched MALSD
search for TDT heads, its default beam search for RNN-T ones, matching NeMo token for token. Without a language
model a beam gains little; on clean LibriSpeech, TDT's MALSD cut the word error rate by about a tenth and RNN-T's
beam not at all, at several times greedy's decoding time. CTC heads decode greedily only.

### Long recordings

Loaded with a Silero VAD (`vad_model_id` in the engine spec, or `TranscriptionModelBuilder::with_vad_model_id`),
Parakeet cuts a recording longer than 5 minutes at its silences into windows of at most 2 minutes, transcribes
each, and joins them with their timestamps in place; stretches without speech are skipped, and the 24-minute
bound no longer applies.

```python
spec = t.EngineSpec(
    model=t.ModelSelectedTranscription(model_id="nvidia/parakeet-tdt-0.6b-v3", vad_model_id="silero-vad-v6.gguf")
)
```

## Nemotron-3 Diarization: who speaks when

```bash
inference serve -m nvidia/Nemotron-3-Diarization
```

Nemotron-3 Diarization (a streaming Sortformer) tracks up to 8 speakers, giving each a speech probability for
every 10 ms of audio. It runs its offline configuration: chunks of 340 encoder frames (2.72 s) with 40 frames of
lookahead, an arrival-order speaker cache carrying who has spoken across chunks. A speaker's segments are its
runs of frames past `threshold` (0.5); `response_format=rttm` gives NIST RTTM lines for scoring tools.

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/audio/diarization -F file=@meeting.wav -F response_format=rttm
```

</TabItem>
<TabItem label="Python">

```python
spec = t.EngineSpec(model=t.ModelSelectedDiarization(model_id="nvidia/Nemotron-3-Diarization"))

with ir.Engine(spec) as engine:
    with open("meeting.wav", "rb") as f:
        result = engine.diarization(f.read())
    for segment in json.loads(result.data)["segments"]:
        print(segment["speaker"], segment["start"], segment["end"])
```

</TabItem>
<TabItem label="Rust">

## Streaming Sortformer v2: who speaks when, from a `.nemo`

```bash
inference serve -m nvidia/diar_streaming_sortformer_4spk-v2.1
```

Streaming Sortformer v2.1 tracks up to 4 speakers, giving each a speech probability for every 80 ms of audio.
It loads straight from NVIDIA's `.nemo` checkpoint (the file, a directory holding one, or a Hugging Face repo)
and runs the schedule the checkpoint ships: chunks of 188 encoder frames (15 s) with one frame of context each
side, behind a 188-frame speaker cache. Requests and responses are those of Nemotron-3 above; only
`frame_seconds` differs.

```python
spec = t.EngineSpec(model=t.ModelSelectedDiarization(model_id="nvidia/diar_streaming_sortformer_4spk-v2.1"))
```

## Nemotron streaming ASR

```bash
inference serve -m nvidia/nemotron-3.5-asr-streaming-0.6b
```

`nemotron-speech-streaming-en-0.6b` (English) and `nemotron-3.5-asr-streaming-0.6b` (multilingual) are
FastConformer RNN-T recognisers trained for cache-aware streaming: causal convolutions and attention limited
to a window of chunks. They load from the transformers layout like Parakeet and are transcribed over the whole
recording with the attention window they were trained with, which gives the streaming result; like Parakeet,
they take 24 minutes in one pass, and longer recordings with a VAD. Nemotron-3.5 takes the request's `language` (`de-DE`, `de`, ... from its
`processor_config.json`) as a prompt, or identifies the language itself when none is given, and
`verbose_json` reports it either way. A language outside its list is refused.

```bash
curl http://localhost:1234/v1/audio/transcriptions -F file=@clip.wav -F language=de-DE -F response_format=verbose_json
```

### Streamed transcription

These checkpoints can also transcribe audio as it arrives. A session takes mono audio in pieces of any size, and
each push returns the text the audio so far completes. The model emits text a chunk at a time:
- the English model's chunk is 14 frames, 1.12 s;
- 3.5's is 4 frames, 0.32 s.

So a short push often adds nothing. Finishing returns the rest and the whole transcript in the session's
`response_format`. That transcript is the one the upload endpoint gives for the same audio: the model makes the
same decisions chunk by chunk as over the whole recording. Audio at another `sample_rate` is resampled to the
model's 16 kHz.

On CUDA a session runs at about 50x real time with the English model, so live audio keeps well ahead. On CPU it
runs at about real time.

<Tabs>
<TabItem label="Python">

```python
import inference_rs as ir

with ir.Engine(spec) as engine:
    with engine.transcription_session('{"sample_rate": 24000, "language": "en-US"}') as session:
        for pcm16 in microphone_chunks():  # little-endian 16-bit mono at 24 kHz
            print(session.push(pcm16), end="", flush=True)
        last, transcript = session.finish()
```

</TabItem>
<TabItem label="Rust">

```rust

let session = model.transcription_session(TranscriptionSessionRequest::new(24_000)).await?;
for chunk in microphone_chunks() {
    print!("{}", session.push(&chunk).await?); // f32 samples, or push_pcm16 for bytes
}
let (last, transcript) = session.finish().await?;
```

Over HTTP, `GET /v1/realtime?intent=transcription` serves these sessions as OpenAI's Realtime transcription
sessions. The OpenAI SDKs connect unchanged:

```python
from openai import AsyncOpenAI

client = AsyncOpenAI(base_url="http://localhost:1234/v1", api_key="unused")
async with client.realtime.connect(extra_query={"intent": "transcription"}) as conn:
    await conn.session.update(session={"type": "transcription", "audio": {"input": {
        "format": {"type": "audio/pcm", "rate": 24000}, "turn_detection": {"type": "server_vad"}}}})
    await conn.input_audio_buffer.append(audio=base64_pcm16)  # as the microphone fills
    async for event in conn:
        if event.type == "conversation.item.input_audio_transcription.delta":
            print(event.delta, end="", flush=True)
```

See [OpenAI compatibility](/reference/openai-compatibility/#realtime-transcription-sessions) for the events and the
energy-based server VAD.

Other notes:
- **Models:** sessions take a cache-aware streaming checkpoint only. A model that transcribes whole recordings (Parakeet TDT, RNN-T, CTC) refuses one. A session stays on the model it opened on.
- **Decoding:** sessions decode greedily, and audio is taken at 8 to 192 kHz.
- **Limits:** a model holds up to 64 open sessions, shared by every API key. Each holds about 15 MB of caches and is released when it finishes, when it is closed (dropped, freed or disposed), when a push fails, or after 10 minutes without a push. So a live client pushes its silence too.
- **Timing:** resampled audio reaches the model about 2 ms late, as an upload's does.
- **Uploads:** sessions share the model with uploads, so a push waits behind any whole recording the model is transcribing. Give live audio a model of its own.

## Silero VAD: voice activity

Silero VAD (v6, 16 kHz) gives a speech probability for every 32 ms of audio and cuts speech segments from
them exactly as the reference `get_speech_timestamps` does. It loads from a small GGUF (about 1.2 MB, F32)
made from the official weights, which `mlx-community/silero-vad-v6` republishes:

```bash
hf download mlx-community/silero-vad-v6 model.safetensors --local-dir silero
cargo run -p inference-models-speech --example silero_vad_gguf -- --weights silero/model.safetensors silero-vad-v6.gguf
inference serve -m silero-vad-v6.gguf
```

A GGUF file, a directory holding one, or a Hugging Face repo holding one all load. Audio at other rates is
resampled to 16 kHz, where the reference runs its separate 8 kHz model or decimates 48 kHz, so segments at
those rates can differ slightly from the reference's.

<TabItem label="HTTP">


## Voxtral Realtime: audio in, text out

```bash
inference serve -m mistralai/Voxtral-Mini-4B-Realtime-2602
```

The auto-loader recognizes the Voxtral Realtime layout from `params.json`,
`consolidated.safetensors`, and `tekken.json`. The earlier `VoxtralForConditionalGeneration`
architecture is not supported.

Voxtral Realtime uses the multimodal chat request shape: audio is an input content part and the
response is its transcription. The supported checkpoint is intended for transcription; the text
part in these examples does not imply support for summarization, speaker analysis, or other audio
tasks.

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "messages": [{
      "role": "user",
      "content": [
        {"type": "audio_url", "audio_url": {"url": "https://raw.githubusercontent.com/google-gemma/cookbook/refs/heads/main/apps/sample-data/journal1.wav"}},
        {"type": "text", "text": "Transcribe this."}
      ]
    }]
  }'
```

</TabItem>
<TabItem label="Python">

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedMultimodalPlain(
        model_id="mistralai/Voxtral-Mini-4B-Realtime-2602",
        arch=t.MultimodalLoaderType.VOXTRAL,
    )
)

with ir.Engine(spec) as engine:
    response = engine.chat(
        t.ChatCompletionRequest(
            model="default",
            messages=[
                t.Message(
                    role="user",
                    content=[
                        {"type": "audio_url", "audio_url": {"url": "file:///absolute/path/clip.wav"}},
                        {"type": "text", "text": "Transcribe this audio."},
                    ],
                )
            ],
            max_tokens=256,
            temperature=0,
        )
    )
    print(response.choices[0].message.content)
```

## Dia: text-to-speech

`/v1/audio/speech` matches OpenAI:

```bash
inference serve -m nari-labs/Dia-1.6B
```

Dia understands dialogue speaker tags such as `[S1]` and `[S2]`, and nonverbal parentheticals such as `(laughs)` or `(coughs)`. Use them in the `input` string when you want dialogue or expressive speech.

Its sampling is set when the model loads: a speech model spec takes `generation` with any of `max_tokens`, `cfg_scale`, `temperature`, `top_p` and `top_k`, and leaves the rest at Dia's defaults (`cfg_scale` 3, `temperature` 1.3, `top_p` 0.95, `top_k` 35).

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "input": "[S1] Hello. This is a test of the text-to-speech system.",
    "response_format": "wav"
  }' \
  --output out.wav
```

- Output: raw audio bytes.
- `response_format`: only `wav` and `pcm` are read; `mp3`/`opus`/`aac`/`flac` return a validation error.
- Dia ignores `voice`, `speed`, `phonemes`, `seed` and `instructions`; Kokoro reads all but `instructions` (below).

</TabItem>
<TabItem label="Python">

```python
from pathlib import Path

import inference_rs as ir

    audio = engine.speech_generation(
        t.SpeechGenerationRequest(
            input="[S1] mistral r s can generate speech locally.",

```

## Kokoro: text to speech

```bash
inference serve -m hexgrad/Kokoro-82M
```

Kokoro loads from its PyTorch release: `config.json`, `kokoro-v1_0.pth` (or a `model.safetensors` with
the same tensor names), and every voice pack under `voices/` (`.pt` from the release, or raw
little-endian f32 `.bin` packs of 510 x 256 values). It speaks at 24 kHz.

It also loads [audio.cpp](https://github.com/0xShug0/audio.cpp)'s Kokoro GGUF (architecture `kokoro_tts`,
such as the multilingual `kokoro-82m-q8_0.gguf`), which carries its config and all 54 voices:

```bash
inference serve -m /path/to/kokoro-82m-q8_0.gguf
```

Pass the file, or a directory holding just that GGUF; the auto loader recognizes it. Its matrices are Q8_0 and its
convolutions BF16, so its audio differs measurably from the full-precision release, though not in kind.

Kokoro reads plain text: `input` is phonemized by
[vernacula-phonemizer](https://github.com/christopherthompson81/vernacula-phonemizer) in the language the
voice's first letter names (`a`: American English, `b`: British English, `e` Spanish, `f` French,
`h` Hindi, `i` Italian, `p` Brazilian Portuguese, `j` Japanese, `z` Mandarin), then rendered into the
phoneme alphabet Kokoro was trained on. A voice with any other prefix needs `phonemes`. The phonemizer's
data downloads from the Hugging Face repo `christopherthompson81/vernacula-phonemizer-data` file by file, a language
on its first use (the default voice's at load), into the usual Hugging Face cache, so `HF_HUB_OFFLINE` and
`HF_HUB_CACHE` apply. `VERNACULA_DATA_DIR`, pointing at a copy of the phonemizer's `data` directory, takes its place.
Without the data, requests with `phonemes` still work. Long text is split at paragraphs,
sentences and clauses so each piece fits the model's context.

Request fields Kokoro reads:

- `phonemes`: Kokoro's own phoneme string, spoken in place of `input`. Characters outside Kokoro's
  vocabulary are dropped, and a string longer than the model's 510-phoneme context is split at spaces.
- `voice`: a voice the model ships, such as `af_heart` (the default when present). Several,
  comma-separated, are averaged into one voice. An unknown voice is rejected with the list of
  available ones.
- `speed`: the speaking rate; 1.0 is the model's own, higher is faster. The model spec's
  `generation.speed` sets the default.
- `seed`: seeds the vocoder's noise, so the same request gives the same audio. Without it each
  request draws a fresh seed.
- `timestamps`: answers with JSON instead of raw audio: `audio` (the `response_format` audio, base64-encoded),
  `content_type`, `duration` in seconds, and `words`, each word of `input` with its `start` and `end` in seconds and
  its canonical `ipa`. The times come from the durations Kokoro predicts for each phoneme, scaled to the audio and
  grouped into the words the phonemizer read them from; a written form read as several words (`$3.14`) is one word
  with all its readings. With `phonemes` there are no source words, so `words` is empty; Dia answers with no words.
