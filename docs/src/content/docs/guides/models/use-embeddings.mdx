Embedding models map text to dense vectors for semantic search, reranking, clustering, and downstream retrieval. inference.rs serves embeddings through the standard OpenAI `POST /v1/embeddings` endpoint, so any tool that already targets that endpoint (LangChain, LlamaIndex, vector stores) works unchanged.

## Loading an embedding model

Two regularly tested options:

- `google/embeddinggemma-300m`: 300M parameters, 768-dim vectors. Good general-purpose default.
- `Qwen/Qwen3-Embedding-0.6B`: 600M parameters, 1024-dim vectors.

```bash
inference serve -m google/embeddinggemma-300m
```

Use `Qwen/Qwen3-Embedding-0.6B` the same way:

```bash
inference serve -m Qwen/Qwen3-Embedding-0.6B
```

### BERT-family encoders

Sentence-transformers checkpoints built on BERT, RoBERTa, XLM-RoBERTa, CamemBERT or DistilBERT (`BertModel`, `RobertaModel`, `XLMRobertaModel`, `CamembertModel`, `DistilBertModel` and their `*ForMaskedLM` classes) load the same way. The class alone marks them as embedders, so they need no `--arch`. Checked against transformers on:

- `sentence-transformers/all-MiniLM-L6-v2`: 22M parameters, 384-dim vectors, mean pooling.
- `BAAI/bge-small-en-v1.5`: 33M parameters, 384-dim vectors, CLS pooling.
- `intfloat/multilingual-e5-small`: 118M parameters, 384-dim vectors, multilingual (prefix inputs with `query: ` or `passage: `).
- `sentence-transformers/all-distilroberta-v1`: 82M parameters, 768-dim vectors.
- `sentence-transformers/multi-qa-distilbert-cos-v1` (DistilBERT): 66M parameters, 768-dim vectors, mean pooling.
- `BAAI/bge-m3`: 568M parameters (XLM-RoBERTa), 1024-dim dense vectors, inputs up to 8192 tokens. Its sparse and multi-vector outputs are not served.

```bash
inference serve -m sentence-transformers/all-MiniLM-L6-v2
```

### RoPE encoders

Two encoder families with rotary positions load the same way, detected by their class:

- `nomic-ai/nomic-embed-text-v1.5` (`NomicBertModel`): 137M parameters, 768-dim vectors, inputs up to 8192 tokens. Prefix inputs with `search_query: ` or `search_document: ` as its model card describes.
- `nomic-ai/nomic-embed-text-v2-moe` (`NomicBertModel` with MoE layers): multilingual, 475M parameters with 8 experts top-2 every other layer, 768-dim vectors. Its experts run densely (all 8 over every token, the unrouted ones weighted 0), and stay unquantized under ISQ.
- `jinaai/jina-embeddings-v2-base-en` (`JinaBertForMaskedLM`): 137M parameters, 768-dim vectors, inputs up to 8192 tokens. Jina BERT v2 has no position table; ALiBi biases each head's attention by token distance.
- `ibm-granite/granite-embedding-english-r2` (`ModernBertModel`): 149M parameters, 768-dim vectors, inputs up to 8192 tokens. ModernBERT alternates global layers with 128-token sliding-window ones.

Encoders built from Llama-style layers (RMSNorm, SwiGLU, rotary positions) load too:

- `nvidia/llama-embed-nemotron-8b` (`LlamaBidirectionalModel`): Llama 3 layers run bidirectionally, 4096-dim vectors. Its license is NVIDIA's customized non-commercial one.
- EuroBERT (`EuroBertModel`, `EuroBertForMaskedLM`) and NeoBERT (`NeoBERT`, `NeoBERTLMHead`) checkpoints, and embedders fine-tuned from them.

A checkpoint with no `modules.json` (a base encoder such as `EuroBERT/EuroBERT-210m` or `chandar-lab/NeoBERT`) is mean pooled without normalization, the module sentence-transformers adds when it wraps a plain transformers model.

`jinaai/jina-embeddings-v3` (XLM-RoBERTa with rotary positions, 570M parameters, 1024-dim vectors, inputs up to 8192 tokens) carries a LoRA adapter per task: `retrieval.query`, `retrieval.passage`, `separation`, `classification` and `text-matching`. Name one with `task` on the request, as Jina's own API takes it; the task's instruction (`Represent the query for retrieving evidence documents: ` for `retrieval.query`) is prepended to text inputs, and requests with different tasks still batch together. Without a `task`, the base weights embed. Its license is CC BY-NC 4.0.

```bash
curl http://localhost:1234/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{"model": "default", "input": "how do I reset my password?", "task": "retrieval.query"}'
```

The Jina v5 text embedders take `task` the same way. `jinaai/jina-embeddings-v5-text-small` (Qwen3-0.6B, 1024-dim vectors, inputs up to 32K tokens) and `jinaai/jina-embeddings-v5-text-nano` (EuroBERT-210m, 768-dim vectors, inputs up to 8192 tokens) ship one adapter per task in `adapters/`, which load beside the base weights and apply per request, so requests with different tasks still batch together. The tasks are `retrieval.query` and `retrieval.passage` (one retrieval adapter, with a `Query: ` or `Document: ` prefix), `text-matching`, `clustering` and `classification` (each with `Document: `). Name a task on every request: Jina's code has no task-free mode, and without one the base weights embed. The per-task repositories (`jinaai/jina-embeddings-v5-text-small-retrieval` and the rest) have the adapter merged into the weights; they load as plain Qwen3 or EuroBERT embedders, and take the prefix in the input text itself. Their license is CC BY-NC 4.0.

The Jina v1 rerankers do not load yet: their configs name the base `JinaBertModel` class rather than a classifier.

The pooling and normalization come from the repository's `modules.json`, and a `max_seq_length` in `sentence_bert_config.json` caps the input length (256 tokens for all-MiniLM-L6-v2), as sentence-transformers does. `--isq q8_0` keeps these models close to full precision, but 4-bit types lose noticeably on 384-wide layers.

### GGUF embedders

Encoder GGUFs as llama.cpp's converter writes them load with `--format gguf`, quantized or not: `bert` (BERT, RoBERTa and XLM-RoBERTa checkpoints, such as all-MiniLM, bge and bge-m3), `nomic-bert` (nomic-embed-text v1 / v1.5), `nomic-bert-moe` (nomic-embed-text v2), `jina-bert-v2`, `modern-bert` and `neo-bert`.

```bash
inference serve --format gguf -m nomic-ai/nomic-embed-text-v1.5-GGUF -f nomic-embed-text-v1.5.Q8_0.gguf
```

The tokenizer is rebuilt from the GGUF's own vocabulary (BERT's WordPiece, or XLM-RoBERTa's SentencePiece with its normalization table), the pooling comes from its `pooling_type`, and the embedding is L2-normalized, as llama.cpp normalizes by default. A GGUF with `pooling_type` rank loads as a reranker and serves `/v1/rerank`.

`jina-bert-v3` (Jina Embeddings v3) loads with its task adapters: llama.cpp's converter writes each task's LoRA as a `lora-<task>-*.gguf` file beside the base, and the files in the same directory or repository (fetched with the base from a Hub repository such as `second-state/jina-embeddings-v3-GGUF`) become the tasks `task` names on a request, each with the prompt prefix its file carries. The base needs at least one of them.

Embedders with decoder-style layers load from GGUF too: `eurobert` (EuroBERT, and Jina v5 nano's per-task GGUFs), `llama-embed` (Llama bidirectional embedders such as `llama-nemotron-embed-1b-v2`), and a `qwen3` GGUF that names a `pooling_type` (Qwen3-Embedding, Jina v5 small's per-task GGUFs). They are read like the matching chat-model GGUFs and run bidirectionally where the original does. A `llama-embed` GGUF carries no pooling type; it is mean pooled, as its embedders are. Jina's per-task GGUFs take the `Query: ` / `Document: ` prefix in the input text:

```bash
inference serve --format gguf -m jinaai/jina-embeddings-v5-text-small-retrieval -f v5-small-retrieval-Q8_0.gguf
```

Some conversions lose weights the original uses, so they cannot match it:

- llama.cpp's converter drops the pooler of a BERT `*ForSequenceClassification` reranker (such as the ms-marco cross-encoders), which these rerankers score through. Such a GGUF is refused; load the safetensors checkpoint instead. RoBERTa and XLM-RoBERTa rerankers (bge-reranker) keep their head and load.
- nomic-embed-text v2 GGUFs lack the experts' output bias, so they embed as llama.cpp does but not quite as the original (cosine about 0.89 on a short prompt). The safetensors checkpoint is exact.

## Requesting an embedding

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "input": "The cat sat on the mat."
  }'
```

The response includes the vector in `embedding`:

```json
{
  "object": "list",
  "data": [{
    "object": "embedding",
    "index": 0,
    "embedding": [0.123, -0.456, 0.789, ...]
  }],
  "model": "default",
  "usage": {"prompt_tokens": 7, "total_tokens": 7}
}
```

</TabItem>
<TabItem label="Python">

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedEmbedding(
        model_id="google/embeddinggemma-300m",
        arch=t.EmbeddingLoaderType.EMBEDDINGGEMMA,
    )
)

with ir.Engine(spec) as engine:
    response = engine.embeddings(
        t.EmbeddingRequest(
            input=[
                "task: search result | query: What is graphene?",
                "task: search result | query: What is an apple?",
            ],
            truncate_sequence=True,
        )
    )
    print(len(response.data), len(response.data[0].embedding))
```

For Qwen3-Embedding, set `arch=t.EmbeddingLoaderType.QWEN3EMBEDDING` and drop the EmbeddingGemma prompt prefixes.

```rust
use inference::{EmbeddingModelBuilder, EmbeddingRequest};

let model = EmbeddingModelBuilder::new("google/embeddinggemma-300m")
    .build()
    .await?;

let embeddings = model
    .generate_embeddings(
        EmbeddingRequest::builder()
            .add_prompt("task: search result | query: What is graphene?"),
    )
    .await?;
println!("{:?}", embeddings.first());
```

## Batching

Pass a list of strings to embed many at once:

```bash
curl http://localhost:1234/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "input": [
      "The cat sat on the mat.",
      "A dog chased a squirrel.",
      "A raven croaked from the fencepost."
    ]
  }'
```

The `data` array has one entry per input in input order.

## Request fields

Beyond `model` and `input`:

- `encoding_format`: `"float"` (default) returns float arrays. `"base64"` returns each vector as base64-encoded little-endian f32 bytes. This matches OpenAI's compact form.
- `dimensions`: not supported. Passing it returns a validation error rather than silently truncating.
- `task`: inference.rs extension, as Jina's API takes it. Picks one of the model's task adapters and prepends its instruction or prefix to text inputs; a model without adapters, or an unknown task, is a validation error that names the model's tasks.
- `truncate_sequence`: inference.rs extension. `true` truncates inputs that exceed the model's context length (or a sentence-transformers `max_seq_length`) to their start instead of erroring.

## Normalization

Whether vectors are L2-normalized is model-dependent: inference.rs applies the modules the model ships in `modules.json`. EmbeddingGemma includes a `Normalize` module, so its output is already unit-norm; Qwen3-Embedding does not, so its vectors are returned unnormalized. If you compute cosine similarity as a raw dot product and your model does not normalize, normalize on the client first.

To normalize in Python:

```python
import numpy as np

# From the Python SDK; an HTTP response's JSON is response["data"][0]["embedding"].
v = np.array(response.data[0].embedding)
v_normalized = v / np.linalg.norm(v)
```

Many vector stores (FAISS, pgvector) handle normalization internally.

## EmbeddingGemma prompts

EmbeddingGemma works best when the input is prefixed for the task:

| Use case | Prompt form |
|---|---|
| Retrieval query | `task: search result \| query: <query>` |
| Retrieval document | `title: <title or none> \| text: <document>` |
| Question answering | `task: question answering \| query: <question>` |
| Fact verification | `task: fact checking \| query: <claim>` |
| Classification | `task: classification \| query: <text>` |
| Clustering | `task: clustering \| query: <text>` |
| Semantic similarity | `task: sentence similarity \| query: <text>` |
| Code retrieval | `task: code retrieval \| query: <query>` |

Example:

```bash
curl http://localhost:1234/v1/embeddings \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "input": [
      "task: search result | query: What is graphene?",
      "title: none | text: Graphene is a single layer of carbon atoms."
    ]
  }'
```

Qwen3-Embedding does not require these prefixes, but task-specific prefixes can still help keep a retrieval system consistent.

## Using the vectors

Standard pipeline:

1. Embed a corpus offline and store vectors in a vector database (FAISS, Qdrant, pgvector, Pinecone).
2. At query time, embed the query with the same model.
3. Search the store for nearest neighbors.
4. Optionally rerank top results with a reranker.
5. Feed retrieved documents as language model context.

inference.rs handles steps 1, 2, and (with a cross-encoder, below) 4. The rest is the vector store and application logic. The [web search guide](/guides/agents/web-search/) covers using embeddings to rerank search results within an agent.

## Reranking with a cross-encoder

A cross-encoder reads the query and a document together and scores the pair, which ranks a short candidate list more accurately than comparing two embeddings. Load a `*ForSequenceClassification` checkpoint with one label (a BERT, RoBERTa, XLM-RoBERTa, CamemBERT, DistilBERT, ModernBERT or NeoBERT one) and send `POST /v1/rerank`:

- `cross-encoder/ms-marco-MiniLM-L6-v2`: 22M parameters, English.
- `BAAI/bge-reranker-base`: 278M parameters, multilingual.
- `ml6team/cross-encoder-mmarco-german-distilbert-base` (DistilBERT): 66M parameters, German.
- `Alibaba-NLP/gte-reranker-modernbert-base` (ModernBERT): 149M parameters, English, inputs up to 8192 tokens.
- `tomaarsen/reranker-NeoBERT-gooaq-bce` (NeoBERT): 250M parameters, English.

```bash
inference serve -m cross-encoder/ms-marco-MiniLM-L6-v2

curl http://localhost:1234/v1/rerank \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "query": "how do I reset my password?",
    "documents": [
      "Open Settings, choose Account, then select Reset password.",
      "The office opens at nine and closes at five."
    ],
    "top_n": 1,
    "return_documents": true
  }'
```

The response lists `results`, most relevant first. Each result has its document's `index` in the request, its `relevance_score`, and with `return_documents` the document's `text`. The score is the sigmoid of the model's logit, as sentence-transformers' `CrossEncoder.predict` returns; `raw_scores: true` returns the logit itself. Each pair is tokenized with the tokenizer's pair template, segment ids included, and `truncate_sequence` truncates a pair that is too long. A model that does not score a pair with a single logit (an embedding model, or a classifier with several labels) is rejected.

The Rust SDK has `model.rerank_documents(query, documents)`, the Python SDK `engine.rerank(...)`, and the C ABI `inference_rerank`.
