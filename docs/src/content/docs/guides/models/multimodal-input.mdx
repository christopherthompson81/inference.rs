Multimodal models accept the OpenAI content-part message format: `content` is a list of typed parts instead of a string. The heavily tested families are Qwen3-VL (image, video) and Gemma 4 (image, audio, video); per-model modality support is in the [supported models reference](/reference/supported-models/).

<Tabs>
<TabItem label="CLI">

```bash
inference run -m Qwen/Qwen3-VL-4B-Instruct --image photo.jpg -i "What is this?"
```

`--image`, `--audio`, and `--video` each accept multiple values and require `-i`. Interactive mode also auto-detects file paths in prompts:

```text
> Describe this: /path/to/photo.jpg
```

<TabItem label="Python">

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedMultimodalPlain(model_id="Qwen/Qwen3-VL-4B-Instruct"),
    runtime=t.RuntimeSpec(isq="4"),
)

with ir.Engine(spec) as engine, open("photo.jpg", "rb") as photo:
    response = engine.chat(
        t.ChatCompletionRequest(
            model="default",
            messages=[
                t.Message(
                    role="user",
                    content=[
                        {"type": "image_url", "image_url": {"url": "media://0"}},
                        {"type": "text", "text": "What do you see in this image?"},
                    ],
                )
            ],
            max_tokens=256,
        ),
        media=[ir.MediaAttachment(photo.read(), "image/jpeg")],
    )
    print(response.choices[0].message.content)
```

[Full example](/examples/python/qwen3-vl/).

## Content parts and URL forms

Three part types carry media: `image_url`, `audio_url`, and `video_url`, each wrapping a `{"url": ...}` object. The
engine reads two forms itself:

- `media://N`: the Nth attachment passed beside the request (Python `media=[ir.MediaAttachment(...)]`, C#
  `MediaAttachment`, the C ABI's `inference_media` array; the Rust SDK attaches the images and audio a message carries).
- `data:<mime>;base64,...`: inline base64.

Fetching anything else is the caller's part: a program embedding the engine reads its files or downloads its URLs and
passes the bytes. The HTTP server does that for its clients, so a request to `inference serve` may also name:

- `http(s)://...`: fetched by the server at request time, on the public network only.
- The web UI's uploads.

The server does not read local file paths a request names.

A message can contain any number of parts in any combination the model supports; the model sees them in order:

```json
{
  "role": "user",
  "content": [
    {"type": "image_url", "image_url": {"url": "media://0"}},
    {"type": "image_url", "image_url": {"url": "media://1"}},
    {"type": "text", "text": "What changed between these images?"}
  ]
}
```

## Video

Send video with `--video` on the CLI or a `video_url` part over HTTP/SDKs:

```json
{
  "role": "user",
  "content": [
    {"type": "video_url", "video_url": {"url": "https://example.com/clip.mp4"}},
    {"type": "text", "text": "What happens in this video?"}
  ]
}
```

Non-GIF formats require FFmpeg on the server; install steps and troubleshooting are in [Set up video input](/guides/models/video-setup/).

The engine decodes the file into sampled frames and feeds them through the model's vision path. Per-request frame-sampling controls are not currently exposed.

Qwen3-VL, Gemma 4, and the native Muse Glimmer safetensors checkpoint accept video; see the [supported models reference](/reference/supported-models/) for per-model modality support. [Full example](/examples/server/gemma4-video/).

## Audio

Audio support is model-specific: Gemma 4, Gemma 3n, Phi 4 Multimodal, MiniCPM-O, Voxtral Mini and Small, Voxtral Realtime, Qwen2-Audio, Qwen3-ASR, GLM-ASR, and Granite Speech accept audio parts (the Voxtral models, Qwen2-Audio, Qwen3-ASR, GLM-ASR, and Granite Speech are dedicated audio models; see [speech models](/guides/models/use-speech-models/) and [model family notes](/guides/models/model-family-notes/)). The decision model d1-omni reads an audio clip through `/v1/decisions` instead; see [decision models](/guides/models/use-decision-models/#images-and-audio).

```json
{
  "role": "user",
  "content": [
    {"type": "audio_url", "audio_url": {"url": "media://0"}},
    {"type": "text", "text": "Transcribe this."}
  ]
}
```

OpenAI's `input_audio` part carries the clip inline as base64 (a missing `format` reads as WAV); `audio_url` also takes `http(s)` and `data:` URLs:

```json
{"type": "input_audio", "input_audio": {"data": "<base64>", "format": "wav"}}
```

WAV, MP3, FLAC, and OGG decode natively. Convert other formats with FFmpeg first. [Full example](/examples/python/phi4mm-audio/).

## In-memory images from Python

For bytes or PIL images, pass the encoded bytes as a `MediaAttachment` and name it by position with a `media://N` URL; the engine handles decoding and preprocessing, and nothing is base64-encoded. A `data:` URL also works.

```python
from io import BytesIO
from PIL import Image

img = Image.open("photo.jpg")
buf = BytesIO()
img.save(buf, format="PNG")

request = t.ChatCompletionRequest(
    model="default",
    messages=[
        t.Message(
            role="user",
            content=[
                {"type": "image_url", "image_url": {"url": "media://0"}},
                {"type": "text", "text": "Describe this image."},
            ],
        )
    ],
)
response = engine.chat(request, media=[ir.MediaAttachment(buf.getvalue(), "image/png")])
```

## Mixing modalities in one request

Any combination the model supports works in a single message; order matters:

```python
messages = [
    t.Message(
        role="user",
        content=[
            {"type": "image_url", "image_url": {"url": "media://0"}},
            {"type": "audio_url", "audio_url": {"url": "media://1"}},
            {"type": "text", "text": "Does the commentary match what the chart shows?"},
        ],
    )
]
```

Which modalities a given model accepts is listed in the [supported models reference](/reference/supported-models/).

## Preprocessing

Vision encoders have fixed input resolutions, so each modality is normalized before reaching the model:

- Images are resized to the model's input resolution, preserving aspect ratio (large images are downsized).
- Video uses the decoded frames.
- Audio is resampled to the model's expected rate.

Per-request preprocessing overrides are not exposed. Load-time image bounds are set at launch with `--max-num-images` (default 1), `--max-edge`, and `--max-image-length` (default 1024).
