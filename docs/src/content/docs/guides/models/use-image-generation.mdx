inference.rs serves diffusion models through `POST /v1/images/generations`. The main supported model is FLUX; see the [supported models reference](/reference/supported-models/).

## Running FLUX

```bash
inference serve -m black-forest-labs/FLUX.1-schnell
```

`FLUX.1-schnell` is permissively licensed. `FLUX.1-dev` requires Hugging Face license acceptance: accept on the model page, then authenticate with `inference login`.

The CLI and server always load the fully-resident `Flux` path. To trade speed for a much smaller GPU footprint, use the `FluxOffloaded` loader, which is only selectable from the Python and Rust SDKs shown below:

| Loader | GPU footprint | Availability | Notes |
|---|---|---|---|
| `Flux` | Full model resident | CLI, server, SDK | Fully loaded path. Fastest. |
| `FluxOffloaded` | Much smaller | SDK only | Offloads components to CPU; useful when the full model does not fit. |

### From GGUF files

A local directory in the single-file layout loads FLUX from GGUF, with the T5 text encoder quantized too:

| File | What it is |
|---|---|
| `flux1-dev-Q8_0.gguf` (or `flux1-schnell-*.gguf`) | The FLUX transformer, quantized |
| `ae.safetensors` | The FLUX autoencoder |
| `t5-v1_1-xxl-encoder-*.gguf` (optional) | The T5-XXL text encoder, quantized, in llama.cpp naming |
| `clip_l.safetensors` (optional) | The CLIP-L text encoder |

```bash
inference serve -m /path/to/flux-files
```

The directory needs exactly one `flux<N>-dev*.gguf` or `flux<N>-schnell*.gguf` and at most one `t5*.gguf`. The
transformer config is read off the GGUF's tensors. The T5 and CLIP configs and tokenizers, and any text encoder missing from the directory, come from the Hugging
Face Hub. FLUX.1-dev at Q8_0 with a Q8_0 T5 needs roughly 18 GB of GPU memory; quantized weights cannot be offloaded,
so the GGUF layout loads with `Flux`, not `FluxOffloaded`.

Generating an image:

<Tabs>
<TabItem label="HTTP">

```bash
curl http://localhost:1234/v1/images/generations \
  -H "Content-Type: application/json" \
  -d '{
    "model": "default",
    "prompt": "A photograph of a golden retriever wearing a scarf in autumn leaves.",
    "n": 1,
    "height": 1024,
    "width": 1024
  }'
```

The response is JSON with a `data` array. Each entry has either `url` or `b64_json`, controlled by `response_format` (default `url`); see [Request fields](#request-fields) and [Output handling](#output-handling).

</TabItem>
<TabItem label="Python">

```python
import inference_rs as ir
from inference_rs import types as t

spec = t.EngineSpec(
    model=t.ModelSelectedDiffusionPlain(
        model_id="black-forest-labs/FLUX.1-schnell",
        arch=t.DiffusionLoaderType.FLUX_OFFLOADED,
    )
)

with ir.Engine(spec) as engine:
    response = engine.image_generation(
        t.ImageGenerationRequest(
            prompt="A vibrant sunset in the mountains, high quality.",
            response_format=t.ImageGenerationResponseFormat.URL,
        )
    )
    print(response.data[0].url)
```

</TabItem>
<TabItem label="Rust">

```rust
use inference::{
    DiffusionGenerationParams, DiffusionLoaderType, DiffusionModelBuilder,
    ImageGenerationResponseFormat,
};

let model = DiffusionModelBuilder::new(
    "black-forest-labs/FLUX.1-schnell",
    DiffusionLoaderType::FluxOffloaded,
)
.build()
.await?;

let response = model
    .generate_image(
        "A vibrant sunset in the mountains, high quality.".to_string(),
        ImageGenerationResponseFormat::Url,
        DiffusionGenerationParams::default(),
        None,
    )
    .await?;
println!("{}", response.data[0].url.as_ref().unwrap());
```

## Request fields

| Field | Default | Notes |
|---|---|---|
| `prompt` | required | Text prompt. |
| `n` | 1 | Number of images. |
| `height` | 720 | Output height in pixels. |
| `width` | 1280 | Output width in pixels. |
| `response_format` | `"url"` | `"url"` (response carries the path that serves the PNG from the file store in `url`) or `"b64_json"` (response carries the base64-encoded PNG in `b64_json`). |

`size` (the OpenAI string form) is not supported. Use `height` and `width`.

## Memory notes

FLUX is memory-hungry at native precision: the model is roughly 12B parameters, and the T5 XXL text encoder adds a large memory footprint. For low-memory hosts, use the `FluxOffloaded` loader (SDK only) from the [Running FLUX](#running-flux) table.

For a smaller footprint without offloading, load FLUX and T5 from GGUF ([From GGUF files](#from-gguf-files)).

Diffusion models do not support [ISQ (in-situ quantization)](/reference/quantization-types/). Load them at native precision instead of passing `--quant` or `--isq`; they are generally more sensitive to quantization than language models.

## Output handling

With `url` (the default), the PNG goes into the engine's [file store](/reference/http-api/) and `url` is the path that
serves it, `/v1/files/<id>/content`, including any prefix the router is nested under. Like other stored files it
expires after 30 minutes, or sooner if the model is unloaded, the server restarts, or newer files push the
model's store past its 1 GiB cap. Use `b64_json` to keep an image out of the store. Over HTTP, fetch it from the server; through the Python SDK or the C ABI, read it by id:

```bash
curl -o out.png http://localhost:1234/v1/files/<id>/content
```

```python
file_id = response.data[0].url.split("/")[-2]
with open("out.png", "wb") as f:
    f.write(engine.file_content(file_id).data)
```

The Rust SDK (`generate_image`) has no server to serve from, so with `url` it writes the PNG to its `save_file`
argument, or to `image-generation-<uuid>.png` in the working directory, and returns that path.

With `b64_json`, `b64_json` is the base64-encoded PNG, as in OpenAI's API:

```python
import base64

with open("out.png", "wb") as f:
    f.write(base64.b64decode(response.data[0].b64_json))
```
