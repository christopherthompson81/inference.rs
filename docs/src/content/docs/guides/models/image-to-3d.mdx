---
title: 3D models from an image
description: TRELLIS.2 turns one image of an object into a textured mesh (GLB), or paints a mesh you supply from an image; Idol turns it into 3D Gaussian splats; JoVox generates its voxel structure, which TRELLIS.2's second stage can mesh. BiRefNet removes the background first.
---

Four commands turn an image of an object into 3D:

- `inference image-to-3d` runs TRELLIS.2 end to end: a textured mesh (`model.glb`, its PBR volume baked into base
  color and metallic-roughness textures) from its own sparse structure, shape and texture stages.
- `inference texture-mesh` paints a mesh you already have from the image, with TRELLIS.2's texturing pipeline.
- `inference image-to-splat` runs Idol: the object as 3D Gaussian splats (PLY and SPZ), with the camera the image was
  seen from.
- `inference voxels` runs JoVox for the object's voxel structure and meshes it with TRELLIS.2's shape stage
  (geometry only).

All four remove the background of an opaque image with BiRefNet first, and take an object on a transparent background as
it is. `image-to-3d` and `image-to-splat` also write the object as a closed solid to 3D print
([Printable STL](#printable-stl)).

## TRELLIS.2 end to end

```bash
inference image-to-3d --image chair.jpg --out chair/
inference image-to-3d --image chair.png --out chair/ --variant 512 --seed 3
```

| Flag | Default | Meaning |
|---|---|---|
| `--variant` | `1024-cascade` | The reference's pipeline types. `1024-cascade`: shape at 512, upsampled and sampled again at 1024, texture at 1024 (the reference's default). `1536-cascade`: the same at 1536, stepping down by 128 while the upsampled cells number 49152 or more (never below 1024), texture with the 1024 model. `1024`: everything at 1024 on a 64^3 structure. `512`: everything at 512, faster and coarser |
| `--seed` | 0 | Seeds every stage's noise |
| `--remove-background` | off | Run BiRefNet even when the image has transparency of its own |
| `--texture-size` | 2048 | The baked textures' width and height |
| `--remesh` | off | Rebuild the surface first as a closed shell (narrow-band dual contouring of the distance to it, as `to_glb`'s remesh): watertight, single-sided, but about half its faces go to the inside of the shell |
| `--vertex-colors` | off | Per-vertex color and material instead of baked textures: no unwrapping or baking, about 5 s faster |
| `--faces` | 1000000 | Faces the exported mesh is simplified to (1000 to 10 million) |
| `--samples` | 1 | Results to make, up to 8: the i-th is seeded `--seed` + i and matches a run of one with that seed; each model loads once for all of them, and more than one go in folders `1`, `2`, ... under `--out` |
| `--print-size` | 100 | The printable STL's longest side in millimetres (5 to 2000); see [Printable STL](#printable-stl) |
| `--{structure,shape,texture}-steps` | 12 | Sampling steps of that flow (1 to 100) |
| `--{structure,shape,texture}-guidance` | 7.5, 7.5, 1 | Classifier-free guidance strength (1: none) |
| `--{structure,shape,texture}-guidance-rescale` | 0.7, 0.5, 0 | How far the guided prediction is rescaled toward the conditioned one's spread (0 to 1) |
| `--{structure,shape,texture}-rescale-t` | 5, 3, 3 | The timestep schedule's shift (1: uniform) |
| `--trellis2`, `--trellis-large`, `--dinov3`, `--birefnet` | fetched | Local checkpoint folders |
| `--cpu` | off | Run on the CPU (very slow) |

The sampler defaults are the checkpoint's `pipeline.json`; the guidance applies only within each flow's guidance
interval (0.6 to 1 of the schedule, 0.6 to 0.9 for texture).

The stages: DINOv3 conditions at 512^2 (and 1024^2 past 512); a dense flow samples a 16^3 structure latent that
TRELLIS-image-large's decoder turns into occupancy (pooled to 32^3, or 64^3 for `1024`); shape latents are sampled on
those cells (at 512 or 1024, then for a cascade on the cells the shape decoder upsamples them to, at 1024 or 1536);
texture latents beside them; the shape
decoder extracts the surface from a flexible dual grid and the texture decoder, following its subdivisions, a volume
of base color, metallic, roughness and alpha. The export follows TRELLIS.2's `to_glb` without its remesh: small holes
filled, the mesh simplified to at most a million faces and its topology cleaned (duplicate faces, non-manifold edges,
specks, winding), clustered within 30 degree normal cones and unwrapped with xatlas into one atlas, each cluster one
chart unless it would overlap itself (the reference grows xatlas's own charts inside wider clusters: about twice the
unwrap time for an atlas of the same quality); each covered texel is placed on
the extracted surface and given the volume's trilinear attributes, and the texels between charts are inpainted so
seams don't bleed.

On an RTX 3090 with an 8-core CPU, the robot example: `1024-cascade` 40 s, plus 3 s for the printable STL (the
export's cleanup, unwrap and inpainting march run on the CPU while the texture is sampled, leaving about 2.5 s after it) at a 6.1 GB GPU peak and 2.5 GB of host
memory; `--remesh` 45 s at 6.5 GB (its remesh outlasts the texture stage); `--vertex-colors` 38 s. `512` takes
20 s plus its export, `1024` 38 s at 6.4 GB. Two samples of `1024-cascade` take 76 s, against 82 s for two runs, at
the same peaks. `1536-cascade` takes 98 s at 9.4 GB: its 18,700 cells make the second
shape pass and the texture pass several times longer (attention grows with the square of the cells). The reference's
`1536_cascade` runs out of memory on the same 24 GB GPU.

```
chair/
  model.glb      the unwrapped mesh with normals, a base color + alpha texture and a metallic-roughness texture
                 (with --vertex-colors: COLOR_0 = base color and alpha, _METALLIC and _ROUGHNESS per vertex)
  mesh.ply       the GLB's mesh, geometry only
  print.stl      the object as one closed solid to 3D print, in millimetres, +z up, standing on z = 0
  prepared.png   the object as cut out
  meta.json      variant, resolution, cell and face counts, the print's size, faces and volume, timing
```

The GLB sits in the unit cube centered on the origin, y up as glTF expects (the PLY keeps TRELLIS's z up). The baked
material is opaque, and double-sided unless remeshed. With `--vertex-colors`, glTF viewers show `COLOR_0`, and the material's metallic
and roughness factors are the vertices' means.

As a server job: `{"kind": "image_to_3d"}` with one image, optionally `seed`, `variant` (`"1024_cascade"`,
`"1536_cascade"`, `"1024"` or `"512"`), `remove_background`, `vertex_colors`, `texture_size`, `remesh`, `faces`,
`print_size_mm`, `samples` (several go under `model/1`,
`model/2`, ..., the report then a `samples` list), and
`structure_sampler`, `shape_sampler` and `texture_sampler` (each with optional `steps`, `guidance_strength`,
`guidance_rescale` and `rescale_t`); outputs under `model/`. The web UI's 3D tab has these under **Advanced**.

## Painting a mesh

```bash
inference texture-mesh --mesh chair.glb --image chair.jpg --out chair-painted/
```

| Flag | Default | Meaning |
|---|---|---|
| `--mesh` | required | The mesh: `.glb` (every triangle primitive of its default scene, placed by its nodes), `.obj` or `.ply` (ASCII or binary). glTF and OBJ are y up; a PLY is read as written, so give it y up too |
| `--resolution` | 1024 | The grid the mesh is encoded at, 512 or 1024 (512: about a third of the time, coarser) |
| `--texture-size` | 2048 | The baked textures' width and height |
| `--unwrap` | off | Lay out new texture coordinates even when the mesh has its own |
| `--seed`, `--texture-{steps,guidance,guidance-rescale,rescale-t}` | 0, `pipeline.json`'s | The texture flow's noise and sampler, as in `image-to-3d` |
| `--remove-background` | off | Run BiRefNet even when the image has transparency of its own |

The mesh is centered in the unit cube with its longest side just inside it and turned z up, as TRELLIS.2's
`preprocess_mesh` does; its surface becomes a flexible dual grid (o_voxel's `mesh_to_flexible_dual_grid`), which the
shape encoder turns into latents on the 64^3 cells it occupies. The texture flow samples PBR latents beside those under
the image's DINOv3 tokens, and the texture decoder unfolds them back onto the mesh's own surface cells. The bake
samples that volume at every texel of the mesh's texture coordinates, kept when the mesh has one set of them (one
primitive whose texture coordinates are all given), otherwise from an unwrap, and inpaints between charts. The mesh is
not cleaned or simplified.

`model.glb` holds the mesh in the unit cube, y up, double-sided, with base color and metallic-roughness textures;
`prepared.png` and `meta.json` sit beside it. On an RTX 3090, a 950K-face mesh takes 18 s at 1024 (7.8 GB GPU peak)
and 6.3 s at 512 (5.7 GB); the reference's pipeline takes 40 s at 1024 with a 10.9 GB peak.

As a server job: `{"kind": "texture_mesh"}` with two files, the mesh (by its extension) and the image, optionally
`seed`, `resolution`, `texture_size`, `unwrap`, `remove_background` and `texture_sampler`; outputs under `model/`. The
web UI's 3D tab has it as **Texture a mesh**.

## Idol Gaussian splats

`inference image-to-splat` runs [Idol](https://huggingface.co/speridlabs/idol): a flow transformer samples the
object's 8192-token latent and the input's camera together, conditioned on the image through DINOv3 ViT-H+/16 and
FLUX.2's VAE; an octree decoder grows anchor points from the latent to level 8, and a Gaussian decoder turns each into
32 Gaussians.

```bash
inference image-to-splat --image chair.png --out chair/
inference image-to-splat --image photo.jpg --out chair/ --mode real --gaussians 524288
```

| Flag | Default | Meaning |
|---|---|---|
| `--mode` | `synthetic` | How tightly the object is cropped: `synthetic` (renders and generated images, 1.2x the object) or `real` (photos, 1.7x) |
| `--seed` | 42 | Seeds the latent noise and the octree's sampling |
| `--gaussians` | 262144 | Gaussians to make, 32768 to 1048576 (a multiple of 32: 32 per anchor) |
| `--steps` | 50 | Euler steps of the flow (1 to 200) |
| `--guidance` | 3 | Classifier-free guidance strength (0: none) |
| `--rescale-t` | 3 | The time grid's shift toward high noise (1: uniform) |
| `--print-size` | 100 | The printable STL's longest side in millimetres (5 to 2000); see [Printable STL](#printable-stl) |
| `--idol`, `--dinov3`, `--vae` | fetched | Idol's folder, DINOv3 ViT-H+/16's `model.safetensors`, a FLUX.2 VAE's `diffusion_pytorch_model.safetensors` |
| `--cpu` | off | Run on the CPU (very slow) |

Idol ships its own BiRefNet, which removes an opaque image's background at 1024^2; an image with transparency keeps
its own outline. The denoiser's blocks run in f16 as the reference's do, its attention summing values in f32 (12,294
tokens of f16 sums drift the velocity by 4%).

```
chair/
  splat.ply      standard 3DGS PLY (degree-0 color, logit opacity, log scales), y down as 3DGS viewers expect
  splat.spz      the same splats as SPZ
  print.stl      the solid the splats enclose, to 3D print, in millimetres, +z up, standing on z = 0
  prepared.png   what the model saw: the object cut out on black, 1024 x 1024
  meta.json      seed, Gaussian count, settings, timing and the input's camera (yaw, pitch, radius, vertical fov)
```

The camera is Idol's z-up object frame: the eye sits at `radius * (sin yaw cos pitch, cos yaw cos pitch, sin pitch)`
looking at the origin. On an RTX 3090 a default run takes 53 s (the 50 sampling steps most of it; the reference takes
49 s) at an 8.1 GB GPU peak, plus about 3 s on the CPU for the printable STL.

As a server job: `{"kind": "image_to_splat"}` with one image, optionally `seed`, `mode` (`"synthetic"` or `"real"`),
`gaussians`, `steps`, `guidance`, `rescale_t`, `print_size_mm` and `placement`; outputs under `splat/`. The web UI's
3D tab has it as **Splats from an image**, opening in the splat viewer from the input's camera. With `--world-models <folder>`,
checkpoints found there as `idol`, `dinov3-vith16plus-pretrain-lvd1689m/model.safetensors` and
`FLUX.2-klein-4B/vae/diffusion_pytorch_model.safetensors` are used instead of fetching them.

## Printable STL

Both image jobs write `print.stl` beside their models: the object as one closed, single-shell solid that slicers take
as it is, in millimetres with its longest side `--print-size` (100 by default), centered over the origin and standing
on z = 0. The web UI shows it under **View printable** and sets its size as **Print size (mm)**.

It is made on a grid over the object (384 cells across for TRELLIS.2, 256 for Idol). The grid's points are marked
from the source: TRELLIS.2's sparse voxels at 1024 (its meshes leave gaps where a cell's neighbours are missing, and
the voxels don't), or Idol's Gaussians, their opacity summed. A flood from outside, closed over gaps of a couple of
cells (up to about six for Idol, whose shells can have gaps that would hollow the object out), finds everything it
can't reach, so hollow interiors fill. For TRELLIS.2, parts thinner than about five cells
(open shells, rods, a rope) are thickened to that, about 1.3 mm at 100 mm, while thicker parts keep their size; Idol's
sealed splats are left as they are (thickening counts the small bumps of their surface as thin and grows them into
warts). The largest piece is kept, and its surface extracted (surface nets on the blurred solid, cells that touch only
diagonally joined so no edge has more than two faces), smoothed, and simplified toward 500,000 faces (about 25 MB)
without collapses that would pinch it.

The surface sits within about one cell of the source's, and details finer than a couple of cells are softened. Color
is not carried: STL has none. On an 8-core CPU the export takes about 3 s for the robot or an Idol chair, and up to
12 s for an object as large as its cube with hollow walls (2.7 million faces before simplifying).

## JoVox voxels

`inference voxels` turns one image of an object into its shape in two stages. JoVox, a discrete flow-matching
model, generates the object's occupancy at 4^3, 16^3 and 64^3 in one model, conditioned on the image through DINOv3.
TRELLIS.2's second stage then fills that structure with shape latents under the same image at 1024^2, decodes them to
a 1024^3 flexible dual grid and extracts a mesh, its small holes filled and its faces reduced to at most a million.
`--no-mesh` stops at the voxel structure.

## Run it

```bash
# an object on a transparent background is used as it is; any other image has its background removed
inference voxels --image chair.jpg --out chair/

# local checkpoints, another sample
inference voxels --image chair.png --out chair/ --jovox JoVox-64 --dinov3 dinov3-vitl16 --seed 3
```

| Flag | Default | Meaning |
|---|---|---|
| `--seed` | 0 | The sampler's seed; an image can have more than one plausible structure, and seeds pick among them |
| `--steps` | 72 | Sampling steps, 36 to 108 (the range the model was trained on) |
| `--cfg` | 1.5 | Classifier-free guidance, at least 1 |
| `--temperature` | 0 | 0 takes each cell's most likely occupancy; above 0 samples it |
| `--fill` | 0.74 | The share of the prepared image the object's longest side fills |
| `--remove-background` | off | Run BiRefNet even when the image has transparency of its own |
| `--no-mesh` | off | Stop at the voxel structure |
| `--cpu` | off | Run on the CPU (slow) |

On an RTX 3090 a structure takes 6 to 11 seconds (more voxels, more time) and about 6 GB of VRAM; meshing it adds
about 30 seconds (the shape flow ~14 s, the decoder ~1.5 s, hole filling and simplification on the CPU ~7 s) and takes
the peak to about 9.5 GB.

## Outputs

```
chair/
  prepared.png   what the model sees: the object cut out, centered and scaled to 512 x 512
  voxels.ply     the occupied cells as a cube mesh (only faces between filled and empty cells)
  mesh.ply       the surface: triangles, at most 1M faces
  meta.json      voxel count, mesh counts, settings and timings
```

Both sit in the unit cube centered on the origin, z up: voxel `(x, y, z)` spans `(x, y, z) / 64 - 0.5` to
`(x + 1, y + 1, z + 1) / 64 - 0.5`. The mesh is geometry only (no texture or vertex colors).

## As a server job

A server started with `inference serve` takes the same run as a job:

```bash
curl localhost:1234/v1/jobs -F 'request={"kind": "voxels", "seed": 3}' -F file=@chair.jpg
```

The request may also set `steps`, `cfg_strength`, `temperature`, `fill` and `remove_background`. The job's outputs are `voxels/voxels.ply`, `voxels/prepared.png` (also its preview) and `voxels/meta.json`. With
`--world-models <folder>`, checkpoints found there as `JoVox-64`, `dinov3-vitl16-pretrain-lvd1689m` and `BiRefNet` are
used instead of fetching them.
