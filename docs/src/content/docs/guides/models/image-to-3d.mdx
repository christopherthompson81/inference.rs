---
title: 3D models from an image
description: TRELLIS.2 turns one image of an object into a textured mesh (GLB); JoVox generates its voxel structure, which TRELLIS.2's second stage can mesh. BiRefNet removes the background first.
---

Two commands turn one image of an object into 3D:

- `inference image-to-3d` runs TRELLIS.2 end to end: a textured mesh (`model.glb`, its PBR volume baked into base
  color and metallic-roughness textures) from its own sparse structure, shape and texture stages.
- `inference voxels` runs JoVox for the object's voxel structure and meshes it with TRELLIS.2's shape stage
  (geometry only).

Both remove the background of an opaque image with BiRefNet first, and take an object on a transparent background as
it is.

## TRELLIS.2 end to end

```bash
inference image-to-3d --image chair.jpg --out chair/
inference image-to-3d --image chair.png --out chair/ --variant 512 --seed 3
```

| Flag | Default | Meaning |
|---|---|---|
| `--variant` | `1024-cascade` | `1024-cascade`: shape at 512, upsampled and sampled again at 1024, texture at 1024 (the reference's default). `512`: everything at 512, faster and coarser |
| `--seed` | 0 | Seeds every stage's noise |
| `--remove-background` | off | Run BiRefNet even when the image has transparency of its own |
| `--texture-size` | 2048 | The baked textures' width and height |
| `--remesh` | off | Rebuild the surface first as a closed shell (narrow-band dual contouring of the distance to it, as `to_glb`'s remesh): watertight, single-sided, but about half its faces go to the inside of the shell |
| `--vertex-colors` | off | Per-vertex color and material instead of baked textures: no unwrapping or baking, about 5 s faster |
| `--trellis2`, `--trellis-large`, `--dinov3`, `--birefnet` | fetched | Local checkpoint folders |
| `--cpu` | off | Run on the CPU (very slow) |

The stages: DINOv3 conditions at 512^2 (and 1024^2 for the cascade); a dense flow samples a 16^3 structure latent that
TRELLIS-image-large's decoder turns into occupancy (pooled to 32^3); shape latents are sampled on those cells (at 512,
then for the cascade on the cells the shape decoder upsamples them to, at 1024); texture latents beside them; the shape
decoder extracts the surface from a flexible dual grid and the texture decoder, following its subdivisions, a volume
of base color, metallic, roughness and alpha. The export follows TRELLIS.2's `to_glb` without its remesh: small holes
filled, the mesh simplified to at most a million faces and its topology cleaned (duplicate faces, non-manifold edges,
specks, winding), clustered within 30 degree normal cones and unwrapped with xatlas into one atlas, each cluster one
chart unless it would overlap itself (the reference grows xatlas's own charts inside wider clusters: about twice the
unwrap time for an atlas of the same quality); each covered texel is placed on
the extracted surface and given the volume's trilinear attributes, and the texels between charts are inpainted so
seams don't bleed.

On an RTX 3090 with an 8-core CPU, the robot example: `1024-cascade` 40 s (the export's cleanup, unwrap and inpainting march
run on the CPU while the texture is sampled, leaving about 2.5 s after it) at a 6.1 GB GPU peak and 2.5 GB of host
memory; `--remesh` 45 s at 6.5 GB (its remesh outlasts the texture stage); `--vertex-colors` 38 s. `512` takes
20 s plus its export.

```
chair/
  model.glb      the unwrapped mesh with normals, a base color + alpha texture and a metallic-roughness texture
                 (with --vertex-colors: COLOR_0 = base color and alpha, _METALLIC and _ROUGHNESS per vertex)
  mesh.ply       the GLB's mesh, geometry only
  prepared.png   the object as cut out
  meta.json      variant, resolution, cell and face counts, timing
```

The GLB sits in the unit cube centered on the origin, y up as glTF expects (the PLY keeps TRELLIS's z up). The baked
material is opaque, and double-sided unless remeshed. With `--vertex-colors`, glTF viewers show `COLOR_0`, and the material's metallic
and roughness factors are the vertices' means.

As a server job: `{"kind": "image_to_3d"}` with one image, optionally `seed`, `variant` (`"1024_cascade"` or `"512"`),
`remove_background`, `vertex_colors`, `texture_size` and `remesh`; outputs under `model/`.

## JoVox voxels

`inference voxels` turns one image of an object into its shape in two stages. JoVox, a discrete flow-matching
model, generates the object's occupancy at 4^3, 16^3 and 64^3 in one model, conditioned on the image through DINOv3.
TRELLIS.2's second stage then fills that structure with shape latents under the same image at 1024^2, decodes them to
a 1024^3 flexible dual grid and extracts a mesh, its small holes filled and its faces reduced to at most a million.
`--no-mesh` stops at the voxel structure.

(14 GB).

## Run it

```bash
# an object on a transparent background is used as it is; any other image has its background removed
inference voxels --image chair.jpg --out chair/

# local checkpoints, another sample
inference voxels --image chair.png --out chair/ --jovox JoVox-64 --dinov3 dinov3-vitl16 --seed 3
```

| Flag | Default | Meaning |
|---|---|---|
| `--seed` | 0 | The sampler's seed; an image can have more than one plausible structure, and seeds pick among them |
| `--steps` | 72 | Sampling steps, 36 to 108 (the range the model was trained on) |
| `--cfg` | 1.5 | Classifier-free guidance, at least 1 |
| `--temperature` | 0 | 0 takes each cell's most likely occupancy; above 0 samples it |
| `--fill` | 0.74 | The share of the prepared image the object's longest side fills |
| `--remove-background` | off | Run BiRefNet even when the image has transparency of its own |
| `--no-mesh` | off | Stop at the voxel structure |
| `--cpu` | off | Run on the CPU (slow) |

On an RTX 3090 a structure takes 6 to 11 seconds (more voxels, more time) and about 6 GB of VRAM; meshing it adds
about 30 seconds (the shape flow ~14 s, the decoder ~1.5 s, hole filling and simplification on the CPU ~7 s) and takes
the peak to about 9.5 GB.

## Outputs

```
chair/
  prepared.png   what the model sees: the object cut out, centered and scaled to 512 x 512
  voxels.ply     the occupied cells as a cube mesh (only faces between filled and empty cells)
  mesh.ply       the surface: triangles, at most 1M faces
  meta.json      voxel count, mesh counts, settings and timings
```

Both sit in the unit cube centered on the origin, z up: voxel `(x, y, z)` spans `(x, y, z) / 64 - 0.5` to
`(x + 1, y + 1, z + 1) / 64 - 0.5`. The mesh is geometry only (no texture or vertex colors).

## As a server job

A server started with `inference serve` takes the same run as a job:

```bash
curl localhost:1234/v1/jobs -F 'request={"kind": "voxels", "seed": 3}' -F file=@chair.jpg
```

The request may also set `steps`, `cfg_strength`, `temperature`, `fill` and `remove_background`. The job's outputs are `voxels/voxels.ply`, `voxels/prepared.png` (also its preview) and `voxels/meta.json`. With
`--world-models <folder>`, checkpoints found there as `JoVox-64`, `dinov3-vitl16-pretrain-lvd1689m` and `BiRefNet` are
used instead of fetching them.
